# Kraken project template

A C++ starting point for Windows and Visual Studio 2022, with the solution generated by
[Sharpmake](https://github.com/zzWeeZz/Sharpmake) (a fork with CMake library support).

## Requirements

- Visual Studio 2022 with the "Desktop development with C++" workload
- the .NET SDK (6.0 or later), to build Sharpmake
- git

## Getting started

```
git clone --recursive https://github.com/zzWeeZz/Kraken-ProjectTemplate.git
```

| Script | What it does |
| --- | --- |
| `Build_Solution.bat` | Builds Sharpmake and generates `Engine.sln` at the root. Run it again after adding files or projects. |
| `Build_debug_Solution.bat` | Same, plus a solution to debug the Sharpmake scripts. |
| `Build_Binaries.bat [Debug\|Release\|All]` | Generates the solution and builds it with MSBuild. |

The executables go to `bin\Win64_<Configuration>`, the libraries and intermediate files to `bin-int\`.

## Layout

| Folder | |
| --- | --- |
| `EntryPoint/src` | The executable. |
| `Core/src` | A static library used by `EntryPoint`. |
| `ProjectDefinitions/Common` | Settings shared by all projects: targets, output folders, `KrakenProject` base class. |
| `ProjectDefinitions/Projects` | One `.cs` file per project. |
| `ProjectDefinitions/Vendor` | Third-party libraries. |
| `ProjectDefinitions/Solutions` | The solution. |
| `Vendor/Sharpmake` | Sharpmake, as a git submodule. |

### Adding a project

Make a folder `MyLib/src` at the root and a file `ProjectDefinitions/Projects/sharpmake.mylib.cs`:

```csharp
using Sharpmake;

namespace Kraken
{
    [Sharpmake.Generate]
    public class MyLib : KrakenProject
    {
        public override void ConfigureAll(Configuration conf, Target target)
        {
            base.ConfigureAll(conf, target);
            conf.Output = Configuration.OutputType.Lib;
        }
    }
}
```

Then `conf.AddPrivateDependency<MyLib>(target);` in the project that uses it.

### Adding a third-party library

Libraries with a `CMakeLists.txt` are downloaded from GitHub and built without running CMake,
like CMake's `FetchContent`. See `ProjectDefinitions/Vendor/sharpmake.spdlog.cs`: copy it, change
the URL, tag and CMake target name, and add the dependency where it is used.

The downloads are cached in `Vendor/_deps` (ignored by git). Run `Build_Solution.bat /fetchupdate`
to download again the libraries that follow a branch.

## Updating Sharpmake

```
cd Vendor/Sharpmake
git pull origin main
cd ../..
git add Vendor/Sharpmake
```

The `Build_*.bat` scripts rebuild Sharpmake each time, so the new version is used on the next run.
